**Borderless Checkout** is a next-generation stablecoin payment gateway built for African SMEs and online businesses. It enables merchants to accept on-chain USDC payments on **Base Sepolia (Chain ID 84532)** with automated backend reconciliation, real-time dashboard analytics, and two core AI capabilities:

1. **AI Merchant Chatbot:** Answers merchant financial queries using actual on-chain transaction data through Claude API tool calling.
2. **AI Treasury Agent:** Evaluates outstanding supplier invoices and executes authorized payouts, strictly governed by an **independent policy engine** enforcing non-bypassable spending limits ($500.00).

## Architecture: Modular Monolith

Borderless Checkout follows a clean **modular monolith architecture**, where domain features are organized into isolated, self-contained modules with clear public interfaces:

```text
borderless-checkout/
├── modules/
│   ├── auth/                    # Merchant registration, session, multi-tenant isolation
│   ├── orders/                  # Order lifecycle and unique payment reference generation
│   ├── checkout/                # Customer checkout UI, QR generation, wallet connection
│   ├── blockchain/              # Base Sepolia viem client, USDC contract ABI, on-chain verifier
│   ├── reconciliation/          # Automatic payment-to-order reconciliation & idempotency
│   ├── dashboard/               # Merchant overview, metrics, indicative ZAR exchange rates
│   ├── suppliers/               # Approved vendor registry and invoice management
│   ├── treasury/                # Independent policy engine and spending limit controls
│   ├── ai-chatbot/              # Claude API conversational assistant with read-only tools
│   ├── ai-treasury-agent/       # Claude autonomous agent, reasoning traces & scenario test bench
│   └── audit-logs/              # Immutable audit trail for agent actions & on-chain hashes
├── lib/
│   ├── database/
│   │   ├── drizzle/             # Drizzle ORM schema, relations, and Postgres connection
│   │   │   ├── schema.ts        # All 7 core relational tables and foreign keys
│   │   │   └── db.ts            # Drizzle client with resilient fallback repository
│   │   ├── db.ts                # Unified modular repository layer
│   │   └── seed-data.ts         # African SME seed data (Kigali Fresh, suppliers, orders)
│   ├── blockchain/              # Network parameters and official testnet USDC addresses
│   └── env.ts                   # Validated environment configuration
├── drizzle/                     # Drizzle SQL migrations generated by drizzle-kit
├── app/                         # Next.js 16 App Router (pages & API route handlers)
└── scripts/
    └── test-runner.ts           # Automated integration test suite
```

## Core Modules & Functionality

### 1. Customer Checkout & Blockchain Verification
- **Unique Payment Reference:** Every order generates a distinct reference (e.g., `BC-ORD-KIGALI-001`).
- **Wallet Connection:** Connects via browser-injected wallet (MetaMask, Coinbase Wallet) or QR code.
- **Strict Backend Verification:** Orders are **never** marked as paid based solely on frontend claims. The backend calls Base Sepolia RPC, inspects the transaction receipt, verifies the official Circle USDC contract, validates that the recipient address matches the merchant, and confirms the exact transferred amount.
- **Indicative ZAR Rate:** Shows an indicative South African Rand equivalent (e.g. `1 USDC ≈ R 18.50 ZAR`), clearly labeled as an indicative demo rate rather than a guaranteed settlement rate.
- **Fast-Track Demo Simulation:** Evaluators without testnet gas can trigger a 1-click verified testnet simulation to evaluate the complete end-to-end flow.

### 2. Automatic Payment Reconciliation
- Matches verified on-chain transfers to the correct customer order.
- **Idempotency & Fraud Prevention:** Rejects duplicate transaction hashes from being claimed twice.
- Automatically transitions order status from `PENDING` to `PAID`.

### 3. AI Merchant Chatbot
- Merchant conversational assistant powered by the Claude API.
- Leverages backend tools to answer natural language questions:
  - *"How much have I received today?"*
  - *"Which orders are still unpaid?"*
  - *"Show me my recent transactions."*
  - *"What is my current USDC balance?"*
  - *"Summarise my payment activity this week."*
- **Strict Security Constraint:** Strictly read-only with no transaction execution rights.

### 4. AI Treasury Agent & Independent Policy Engine
- Autonomous agent helping merchants manage outstanding supplier payments.
- **Independent Policy Engine:** All payments must pass through a strict backend policy guard that cannot be altered or bypassed by the AI.
- **Demonstration Scenarios:**
  - **Scenario 1 (Approved):** $100 invoice to approved supplier ("Cape Agro Packaging Ltd") $\le$ $500 spending limit $\rightarrow$ Policy engine APPROVES $\rightarrow$ Executed on Base Sepolia $\rightarrow$ Tx hash logged.
  - **Scenario 2 (Rejected):** $700 invoice exceeds $500 spending limit $\rightarrow$ Policy engine REJECTS $\rightarrow$ On-chain execution is BLOCKED $\rightarrow$ Rejection logged in audit trail.
  - **Unapproved Vendor Guard:** Invoices for unapproved vendors are automatically blocked.

## Getting Started

### 1. Prerequisites
- Node.js $\ge$ 20 (Node 22 or 26 recommended)
- `pnpm` $\ge$ 9 (or `npm`)

### 2. Installation
```bash
git clone https://github.com/your-username/borderless-checkout.git
cd borderless-checkout
pnpm install
```

### 3. Environment Configuration
Copy the example environment file:
```bash
cp .env.example .env
```

Key environment variables:
```env
# Blockchain
NEXT_PUBLIC_BASE_SEPOLIA_RPC=https://sepolia.base.org
NEXT_PUBLIC_BASE_CHAIN_ID=84532
NEXT_PUBLIC_USDC_CONTRACT=0x036CbD53842c5426634e7929541eC2318f3dCF7e
NEXT_PUBLIC_BLOCK_EXPLORER=https://sepolia.basescan.org

# Optional Claude API Key (Deterministic fallback available when unconfigured)
ANTHROPIC_API_KEY=your_anthropic_api_key

# Database (Drizzle ORM with PostgreSQL / Supabase)
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/borderless_checkout

# Required in production for signed merchant sessions (generate at least 32 random characters)
APP_SESSION_SECRET=replace-with-a-random-secret-at-least-32-characters-long
```

*Note: The application includes a pre-seeded in-memory/fallback repository, so you can immediately run and test the app even before connecting a live PostgreSQL database.*

### 4. Database Commands (Drizzle ORM)
```bash
# Generate SQL migrations from schema
pnpm db:generate

# Push schema directly to database
pnpm db:push

# Open Drizzle Studio visual GUI
pnpm db:studio
```

### 5. Run Integration Tests
Verify end-to-end reconciliation, Drizzle models, policy limits, and AI agent execution:
```bash
pnpm test
```

### 6. Start Development Server
```bash
pnpm dev
```
Open [http://localhost:3000](http://localhost:3000) to view the application:
- **Merchant Dashboard:** [http://localhost:3000/dashboard](http://localhost:3000/dashboard)
- **Live Customer Checkout Demo:** [http://localhost:3000/checkout/ord_live_checkout_01](http://localhost:3000/checkout/ord_live_checkout_01)

## User Journeys to Test

### Customer Checkout Journey
1. Open the merchant dashboard and click **"New Order"**.
2. Enter customer reference and amount (e.g. R 925.00 ZAR).
3. Open the generated checkout link.
4. Click **"Connect Wallet"** (Base Sepolia).
5. Click **"Approve & Pay USDC"** or use the **"⚡ Fast-track Demo"** button.
6. The backend verifies the transaction on Base Sepolia and marks the order as `PAID`.
7. Return to the dashboard to see updated revenue and transaction hash linked to BaseScan.

### AI Treasury Agent Journey
1. Navigate to the **"AI Treasury Agent"** tab in the dashboard.
2. Click **"Run Scenario 1 ($100 Approved)"**:
   - The agent inspects the invoice, checks the balance, verifies vendor approval, and submits to the policy engine.
   - The policy engine approves ($100 $\le$ $500), executes the payment, and records the Base Sepolia tx hash.
3. Click **"Run Scenario 2 ($700 Limit Exceeded)"**:
   - The agent evaluates the $700 invoice.
   - The policy engine rejects the request ($700 $>$ $500 limit).
   - No blockchain transaction is submitted, and the rejection reason is logged.
4. View the **"Audit Logs"** tab to inspect the immutable decision trail.
